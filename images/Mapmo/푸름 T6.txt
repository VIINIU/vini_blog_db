Why Mapmo
모든것에 앞서서 Why mapmo, 
왜 맵모라는 새로운 개념을 제시하려 하느냐에 대한 설명입니다.
저희가 아이디어를 착안한 곳은 피크민 블룸이라는 게임인데요.
이 게임은 실제 지도 위에서 특정 장소에 방문했을 때 노출되는 버섯을 공격해서
경험치를 쌓고 실제 장소에 기반해서 엽서나 게임 상의 기념품을 간직 할 수 있는 게임입니다.

바로 이 게임에서 특정 장소에 방문했을 때 나타나는 퀘스트처럼 할 일을 해치울 수 있다면 사용자가 해당 장소에 도착했을 때 해야할 일을 잊지 않고 하는 동시에, 새로운 재미를 줄 수 있지 않을까 하는 생각이 들었습니다.

What’s Mapmo
학교 할 일
- 과사 들러서 교양 학점 질문
- 강의실 대관 예약 하기
- 수업 전 보고서 프린트
맵모의 핵심 기능은 미리 맵모를 설정해둔 장소에 도착하면 해당 장소에서 해야할 일 또는 메모가 표시되는 것 입니다.

이 기능을 구현하기 위해서는 주기적인 사용자의 위치 정보 조회가 필요합니다.
이를 위해서는 사용자가 항상 휴대하는 디바이스인 휴대전화 앱이 가장 적합하다고 판단했습니다.
이와 더불어서 사용자가 해당 장소에 방문한 이후에는 애플리케이션을 켤 필요없이,
메모 리스트를 항상 띄워두는 키링 형태의 하드웨어가 하나 있으면 좋겠다는 아이디어를 기반으로 블루투스 통신을 기반으로 동작하는 투두리스트 디바이스를 하나 추가하게 되었습니다.

Mapmo’s Going On - APP
메모 작성 화면
지도 조회 화면
3-Layer 구조
다음으로 애플리케이션 개발에 대한 이야기입니다.

먼저 UX 측면에서는, 
일반적인 메모 앱의 User Flow를 벤치마킹해서 사용자가 생소함 없이 즉시 사용할 수 있도록 설계하되, 
각 메모에 '위치 정보' 속성을 결합해서 Mapmo 서비스의 핵심 기능을 구현하였습니다.

소프트웨어 구조 측면에서는 
안드로이드의 표준 MVVM 패턴과 구글이 권장하는 'App Architecture' 가이드라인에 따라 3-Layer 구조를 도입하였습니다. 
이를 통해 데이터 계층과 UI 계층을 엄격히 분리하여 유지보수성을 확보하고, 
전반적인 앱의 안정성을 유지할 수 있도록 설계하였습니다.

지도를 활용한 기능은 카카오맵 및 카카오 로컬 API를 통해 구현하였으며, 
현재 기본적인 메모 관리 기능까지 구현이 완료된 상태입니다. 
보고계신 두 화면 모두 실제 구현된 애플리케이션의 테스트 화면입니다.
현재는 Bluetooth를 통해 키링 디바이스와 통신하는 부분과 백그라운드 서비스 기반의 실시간 위치 알림 기능을 구현해 나가고 있습니다.




Mapmo’s Going On - Hardware

다음은 하드웨어 개발 현황입니다.
저희가 키링 형태의 디바이스를 구현 목표로 삼은 만큼 전력소모를 최소화하는데에 포커싱을 하고 하드웨어 구성 요소들을 선택했습니다.
애플리케이션과의 연동 시에 전력 소모를 줄일 수 있는 BLE 통신 사용이 가능한 보드 중에서Espressif라는 벤더에서 공급하는 ESP32 보드를 기반으로 하드웨어를 구성하고 있습니다.하드웨어 개발의 경우에는 로우레벨에서 커스텀 할수록 프로그램 구성을 최대한 가볍게하여 전력소모를 줄일 수 있기 때문에,FreeRTOS라는 리얼타임OS를 기반으로 하는 ESP-IDF 프레임워크를 사용했습니다.

디스플레이에 의한 전력 소모를 줄이기 위해서 리프레쉬시에만 전력을 소모하는 E-ink Display를 부착하여 구현하고 있습니다.

Mapmo’s Going On - Hardware 개발 중 만난 이쓔,,
하드웨어 개발을 하다보면 변수가 참 많은데요..

FreeRTOS는 상당부분 커스텀이 가능한 대신에 
E-ink vendor에서 제공하는 그래픽 라이브러리를 사용할 수 없어서 
컨트롤러를 지원하는 라이브러리를 찾고, e-ink에서만 사용되는 리프레쉬 시그널 같은 부분을 커스텀 했습니다.
원하는 폰트를 utf형태로 바꿔서 넣어보니 한글이 용량이 참 크더라구요.
임베디드 환경에서는 메모리 제약이 크다보니 2000여자만 변환을 해서 메모리에 올려둔 상황입니다.

디스플레이 설정 이후에는 BLE 실행을 시도했는데, RF 초기화 실행시 전력이 튀어서 무한 reboot 을 하는 문제가 있었는데요.
RF initialize 데이터를 미리 저장할 수 있도록 파티션을 설정해서 이 부분 해결하고 개발중에 있습니다.
현재는 해당 디스플레이에 띄울 프레임과 대기화면 등의 도트를 찍고, fusion 을 사용해서 키링 형태의 쉘을 모델링하고 있습니다.
